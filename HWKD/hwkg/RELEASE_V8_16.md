# v8.16: optional hardware hypotheses reach the coding agent

The user explicitly requested useful potential advice even when exact calibration
cannot match, and retaining the existing baseline for HWKD-only followups.

Initial RTX5080 drafts now receive compact TRAIN precision and CUDA AdamW
implementation options. Existing hardware identity removes redundant identity
facts, while the options remain. Verified graph capabilities and the installed
API determine eligibility; task identity alone no longer silences the component.

On a successful parent, exact profitable calibration still has priority. Otherwise
an eligible CUDA AdamW/BF16 parent, including parameter groups, may receive one
fused implementation hypothesis. Separate TRAIN FP16/GradScaler or BF16/ordinary
step hypotheses preserve FP32 parameters and shared evaluation dtype. Unsupported
host/API, debug/merge, failed parent, incompatible flags, already-adopted changes,
blocked profiles and output budget remain respected. FP16 fused acceleration is
not recommended from the prior failed microdiagnostic.

Hypothesis delivery does not require the declared five-second reserve to be
positive. It carries no speedup/net-time or quality claim. Exact measured
projections keep their strict source/runtime/calibration checks. No training
calibration loop, extra provider call, baseline, SDK, parser, search, executor,
scorer, node/reward or generated candidate is altered.

The component also replaces only its own previously inserted block when a reused
prompt gains host facts, preventing duplicated hypotheses. Return/kwargs/native
retry behavior stay intact. Source-only adoption observations cover precision and
literal grouped-AdamW fused options; actual execution and benefit remain separate.
Known unused CE constructors no longer supply measured active-loss metadata;
unknown helpers/aliases/dataflow do not receive a semantic-equivalence certificate.

Validation: offline component/native compatibility and baseline boundary checked;
one existing live GPU calibration identity test is deferred until the frozen v8.15
run ends. No native performance result for v8.16 exists yet. Do not launch from a
manifest with passed:false. Follow with a fresh HWKD-only light4 after full current
validation and previous-root review/archive; compare the cached baseline as a
historical control, never as a fresh simultaneous paired run.

API references: [AdamW](https://docs.pytorch.org/docs/2.14/generated/torch.optim.AdamW.html)
and [automatic mixed precision](https://docs.pytorch.org/docs/2.14/amp.html).
API availability and graph capability are not measured candidate improvements.
