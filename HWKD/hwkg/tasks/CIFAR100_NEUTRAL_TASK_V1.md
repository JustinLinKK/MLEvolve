# CIFAR-100 image classification: hardware-neutral local benchmark

Train one neural image classifier using PyTorch. Predict 100 fine classes (target integers 0..99). The primary metric is top-1 validation accuracy (higher is better), with macro-F1/top-5 secondary. Use seed 42. This is a CNN image-classification workload.

Inputs in ./input/: train.csv (40000 rows), validation.csv (10000 rows), test.csv (10000 rows). train/validation columns id,image_row,target; test id,image_row. Files train_images.npy, validation_images.npy, test_images.npy are uint8 arrays of shape (rows,3,32,32), RGB channel first; access images by image_row, not id. Load with numpy.load(...,allow_pickle=False), optionally mmap_mode='r'. For torchvision/PIL transforms transpose to HWC. Training/validation ids are disjoint original official training indices; test ids 50000..59999. The input split is immutable: all provided training rows each completed epoch (dropping at most one final partial batch allowed), and exactly all provided validation rows for evaluation. Never train on validation or test images/labels, change the split, or call torchvision.datasets.CIFAR100/load the raw official dataset. Official test labels are unavailable and must not be sought.

Resize to exactly 128x128 RGB for BOTH training and evaluation. Training augmentations may vary; evaluation must be deterministic and one prediction per image, no test-time augmentation. Train a single model for at most six epochs, with at least one full epoch completed for a valid trained submission. No ensembling, folds or hyperparameter sweep. A single best-epoch checkpoint or one EMA model is allowed; do not average multiple prediction models. You have 360 seconds per entire candidate execution, including initialization, training, validation, test prediction and output writing. Finish outputs within that budget; early stopping after a completed epoch is allowed. Use available compute within the same execution budget; keep all data/weights offline, and do not install dependencies or download files.

Allowed pretrained backbones and weight enums are torchvision.models.resnet18 / ResNet18_Weights.IMAGENET1K_V1, resnet34 / ResNet34_Weights.IMAGENET1K_V1, resnet50 / ResNet50_Weights.IMAGENET1K_V2. These exact files are already cached under TORCH_HOME/checkpoints, with torch.hub directory configured identically: resnet18-f37072fd.pth, resnet34-b627a593.pth, resnet50-11ad3fa6.pth. Replace classifier with 100 outputs. A randomly initialized CNN is allowed; no other pretrained models or external datasets. Aggregate process physical RAM (PSS, shared fork pages counted once) must remain at most 31GiB. Choose training strategy and implementation yourself; do not assume a particular accelerator model or runtime version.

Save ./working/validation_predictions.csv with exactly columns id,target, ids in ORIGINAL validation.csv row order. Save ./working/validation_probabilities.npy: float probabilities shape (10000,100), columns correspond to classes 0..99, all finite, each row sums to 1, argmax agrees with target. Save ./submission/submission.csv with exactly columns id,target in ORIGINAL test.csv row order; target integers 0..99. Create directories as needed. Outputs must be freshly produced by this candidate; never reuse preceding outputs. Print validation accuracy, macro-F1 and actual completed epochs. Independent scoring uses fixed validation labels and these outputs.

To measure useful throughput, print one THROUGHPUT_JSON line from a window of at least 20 NORMAL REAL TRAINING steps, excluding initialization/validation: synchronize asynchronous device work at both window boundaries when applicable, report completed_examples, optimizer_steps, skipped_updates, wall_seconds, examples_per_second, actual autocast dtype, model/input memory format, peak_allocated_bytes and window_start_step/window_end_step. Count actual successful work; no extra synthetic benchmark loop, auxiliary load or zero placeholders. If a training run is too short or this was not measured, state throughput unknown. Log actual model, input dimensions, training rows, epoch count and dtypes. Advice is optional; the outputs and fixed validation contract are mandatory.

Budget clarification: the six full-data gradient-training epochs include any head-only warmup. At least one full epoch must complete. No standalone training-image pass for BN recalibration or statistics fitting. SAM may use two forwards inside one minibatch update. All validation/test outputs must finish inside the 360-second candidate budget.

Task provenance: this is a custom public CIFAR-100 preset-goal benchmark, not a verbatim Kaggle competition. The shared task specifies data, quality/output goals and common budgets; no host-specific hardware profile or precision/optimizer recommendation is provided here. Runtime discovery by the original agent or its generated solution remains allowed.
