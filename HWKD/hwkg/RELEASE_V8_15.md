# Component scope repair after the v8.14 native comparison

The v8.14 independent local 5+5 search completed three protocol-valid candidates
per arm, with best public accuracy 86.29% versus 83.05%. Every HWKD context was
empty and no hardware advice was adopted. These different generated recipes and
sequential single-seed outcomes do not establish a component performance gain.

Actual generated code replaced ResNet bottleneck forward methods for stochastic
depth. The component previously retained the ordinary full-model source screen;
an own matched fixture could then borrow the standard ResNet optimizer timing.
Known forward/call replacements, deletions and execution hook registrations now
leave calibration work scope unknown. This is a narrow conservative AST screen,
not complete alias, model semantics, training-budget or runtime equivalence proof.
It changes advice eligibility only; native candidates, nodes and rewards stay intact.

The exact observed `channels_first(NCHW,contiguous)` log spelling is accepted as
an NCHW self-report. Ambiguous `non-contiguous` stays unknown. Printed/source-bound
windows remain unverified telemetry and are not treated as measured useful gain.

Baseline, execution, scoring, search, parser, SDK and provider request behavior are
unchanged. Existing graph and calibrations stay unchanged. Native task performance
for this repair is pending; offline fixtures and source replays are not a fair
baseline/HWKD performance comparison.
